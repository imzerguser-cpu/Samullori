# 가락보 학습 도구 설계

## 배경 및 목적

사물놀이(꽹과리, 장구, 북, 징) 교육용 도구. 선생님이 준비한 모범 음원을 재생하면서, 그 음원의 리듬 위치에 맞춰 가락보(리듬보) 위에 현재 치는 칸을 색으로 강조 표시한다. 학생은 소리를 들으며 눈으로 가락보를 따라가면서 연습한다.

핵심 재정의: 이 도구는 "알 수 없는 연주를 듣고 리듬을 추측"하는 문제가 아니라, **이미 알고 있는 가락보와 그 가락보를 연주한 음원을 정렬(synchronize)하는 문제**다. 이 재정의 덕분에 다음이 성립한다.

- 악기 1개 음원 → 가락보 정렬: 온셋(타격 시점) 검출 + 시퀀스 정렬로 충분히 정확하게 가능
- 4개 악기를 각각 따로 녹음해도, 정렬 후 타임스트레칭으로 공통 타임라인에 맞춰 "합주처럼" 재생 가능. 이 과정을 직접 제어하므로 최종 결과물에서 각 시점이 어느 칸인지 100% 정확히 알 수 있음 (실시간 음원 분리가 필요 없어짐)

## 요구사항 요약

1. 악기 1개의 모범 음원 + 그 악기의 가락보를 주면, 음원 재생 위치에 맞춰 가락보 칸이 강조된다.
2. 4개 악기 각각에 대해 1을 독립적으로 수행할 수 있다.
3. 4개 악기를 동시에 재생하면서 4개의 가락보를 동시에 강조 표시할 수 있다. 4개는 실제 합주 녹음이 아니라 따로 녹음한 것을 자연스럽게 이어붙인 것이어도 된다.
4. 화면에 표시할 악기 수(1~4개)와 소리 낼 악기 수(1~4개)를 학생이 자유롭게 선택할 수 있다. 기본은 "표시"와 "소리"가 연동되지만, 필요시 "소리만 끄기"로 분리 조작 가능하다.
5. 가락보는 기존 hwp 표 파일 기반이며, 원본 표의 모양을 최대한 유지한 채 칸 위에 색으로 강조한다.

## 아키텍처

두 단계로 나눈다.

**준비 단계 (오프라인, Python 스크립트 — 새 음원/가락보를 추가할 때 한 번 실행)**

```
가락보 (hwp → 구조화 JSON) ─┐
                            ├─→ [정렬 엔진] ─→ 칸별 타임스탬프 JSON
음원 (.wav/.mp3, 악기별)   ─┘

(4개 악기 모두 준비된 경우)
4개의 칸별 타임스탬프 ─→ [기준 타임라인 선택 + 타임스트레치] ─→ 4개의 정렬된 음원 파일
                                                              + 기준 시간으로 재계산된 4개의 타임라인 JSON
```

**재생 단계 (정적 웹페이지, 서버 불필요)**

- Web Audio API로 준비된 음원 파일들(1~4개)을 하나의 AudioContext에 로드하고 동시에 재생 시작 → 표류 없는 정확한 동기화
- 매 프레임 현재 재생 시각을 각 악기의 타임라인 JSON과 대조해 해당 칸을 하이라이트
- 상단 체크박스로 악기별 표시/소리를 켜고 끔 (기본 연동, 소리만 끄기 옵션 있음)
- "1단계", "최종 단계" 같은 구분은 화면상 별도로 두지 않는다 — 로드된 트랙이 1개면 1단계처럼, 4개면 최종 단계처럼 동작하는 하나의 플레이어로 통합한다.

## 데이터 모델 (가락보)

악기별로 순서가 있는 칸(cell) 리스트를 JSON으로 관리한다.

```json
{
  "instrument": "janggu",
  "cells": [
    {
      "id": "c1",
      "label": "덩",
      "strike_count": 1,
      "measure": 1,
      "bbox": { "x": 10, "y": 20, "w": 40, "h": 30 }
    },
    {
      "id": "c2",
      "label": "쉼",
      "strike_count": 0,
      "measure": 1,
      "bbox": { "x": 50, "y": 20, "w": 40, "h": 30 }
    }
  ],
  "source_image": "scores/janggu_table.png"
}
```

- `strike_count`: 쉼표(0), 한 번 타격(1), 겹채/굴림처럼 한 칸에서 여러 번 타격(2 이상)을 구분
- `bbox`: hwp에서 변환한 원본 표 이미지 위에 하이라이트 박스를 그릴 좌표. 표 구조가 고정이므로 한 번만 만들면 재사용

## 정렬 알고리즘

1. `librosa.onset.onset_detect`로 음원에서 실제 타격 시각 목록을 추출한다.
2. 가락보의 `strike_count`를 펼쳐 "기대 타격 순서" 시퀀스를 만든다.
3. 검출된 타격 개수와 기대 개수가 다를 수 있으므로(놓친 타격, 잡음), 시퀀스 정렬(동적 계획법 기반 매칭)로 최적 대응을 찾는다.
4. 각 칸의 하이라이트 구간은 "그 칸의 첫 타격 시각"부터 "다음 칸의 첫 타격 시각 직전"까지로 정의한다.

## 최종 단계(4트랙 통합) 정렬

1. 4개 악기 각각 위 정렬 과정을 거쳐 칸별 타임스탬프를 확보한다.
2. 기준 타임라인을 정한다 (기본값: 장구 트랙 기준. 장구가 사물놀이에서 장단을 이끄는 역할이기 때문).
3. 나머지 트랙을 `pyrubberband`로 타임스트레치(트랜지언트 보존 모드)해서 기준 타임라인에 맞춘다.
4. 4개를 하나로 믹스하지 않고 **개별 파일로 유지**한다 (음소거 기능을 위해 필요).
5. 4개 트랙 각각의 칸별 타임스탬프를 기준 시간으로 재계산해 JSON으로 출력한다.

타임스트레치 비율이 크면(원래 대비 ±30% 이상) 음질이 부자연스러워질 수 있음을 준비 단계 로그에 경고로 남긴다.

## 검수 도구 (준비 단계 전용, 학생용 아님)

자동 정렬이 항상 완벽하지 않을 수 있다. 파형 위에 자동 매칭된 타임스탬프를 점으로 표시하고, 잘못된 지점을 클릭해 드래그로 수정할 수 있는 간단한 웹 기반 검수 화면을 준비 단계 산출물 확인용으로 제공한다.

## 재생 화면 (웹 플레이어)

- 상단: 악기별 체크박스 4개. 기본은 "표시+소리" 연동. 각 체크박스 옆에 작은 "소리만 끄기" 보조 토글.
- 본문: 선택된 악기 수만큼 가락보 패널을 반응형 그리드로 표시 (1~4개).
- 하단: 재생/일시정지, 배속(0.5x~1x), 특정 장단 구간 반복재생.
- 각 패널에서 현재 칸 위에 반투명 색 박스로 강조.

## 프로젝트 구조


## 에지 케이스

- 쉼표 칸: `strike_count = 0`으로 표현, 정렬 시 타격을 기대하지 않음
- 겹채(장구 양편 동시 타격), 굴림(여러 번 빠른 타격): `strike_count >= 2`로 표현
- 온셋 검출 실패/오검출: 시퀀스 정렬로 1차 보정, 검수 도구로 2차 수동 보정
- 타임스트레치 과도 적용: 경고 로그로 알림 (자동 차단은 하지 않음, 선생님이 판단)

## 테스트/검증 계획

1. 프로토타입: 악기 1개(예: 장구) 음원으로 파이프라인을 통과시켜 파형 위에 자동 검출/정렬 결과를 시각적으로 겹쳐 확인
2. 실제 음원 샘플 여러 개로 정렬 오차(ms 단위) 측정
3. 4트랙 통합 후: 동시 재생해서 귀로 싱크 확인 + 화면 하이라이트가 실제 타격 소리와 일치하는지 확인
4. 웹 플레이어: 표시/소리 체크박스 조합(1개~4개 선택)이 모두 정상 동작하는지 수동 확인

## 확장 여지 (지금은 구현하지 않음)

여러 개의 가락보를 다루게 되면, 음원/가락보 업로드용 웹 서버(방식 C)로 업그레이드하는 것을 고려한다. 지금 설계의 준비 파이프라인과 데이터 스키마는 그대로 재사용 가능하다.
